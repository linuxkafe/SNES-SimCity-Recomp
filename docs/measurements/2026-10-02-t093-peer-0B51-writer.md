# T093 — who writes `$0B51`, measured in the reference build

> **STATE: MEASURED (host only).** The peer core was built and run on the dev
> box; **no Deck measurement backs any number in this file.** Every claim below
> is host-only evidence.

## The question, and the answer

The premise that `$0B51` *is* the city tick was INFERRED, and load-bearing,
because the code believed to advance it provably never runs in our build
(C-041). So: watch it actually get written in a build where the clock moves.

**The writing instruction is `$03:8026` = `INC.w $0B51`, and it DOES execute in
the reference build: 27 times in 9000 frames, first at frame 3857, then on a
strict 4-cycle of +152/+253/+140/+243 frames (788 frames per 4 ticks = 197
frames per tick).**

The premise is therefore corroborated, not refuted — but only for the reference
build, and **not in the sense anyone wanted**, because of the next section.

## Two findings that matter more than the answer

### 1. `$0B51` rising is NOT sufficient for the clock to advance

In the same 9000-frame run, `$0B51` climbs `0000 -> 001B` monotonically while:

| field | value across f3000–f9000 |
|---|---|
| year word `$0B53` | `1900`, never moves |
| population `$0BA5` | `0`, never moves |
| funds `$0B9D` | `20000`, never moves |
| WRAM bytes moved | 50–500 per 120 frames |

So **27 executions of the tick incrementer bought nothing.** Any causal story of
the shape "make `$03:8026` run and the clock advances" is refuted by this run.
This is the most load-bearing sentence in the file.

### 2. The keyboard route reaches "city loaded", not "city running" — in BOTH builds

The peer run loads the city at ~f2985 and then does not simulate. Our build
reaches the *same* loaded state (`$0B53 = 0x076C`, funds 20000, pop 0) at a
similar frame and also does not simulate. **MEASURED, host-only, both cores:**
the route in `scripts/d_city_kbd.script` does not reach a running city in
either project, and the peer is **not** a reference for "a build where the clock
demonstrably advances" — not via this script. What the peer IS, measurably, is
a build that reaches the city-loaded state **and then executes the tick 27
times**, which is precisely the thing ours does not do.

> **What this does NOT establish.** "The route does not reach a running city"
> is a statement about `d_city_kbd.script` as run, on these two cores, for 9000
> frames. It is not a claim that no input sequence reaches a running city in
> either build — that would need a search over sequences, which has not been
> run. And the inference from it ("so the peer cannot be a reference build") is
> **INFERRED from a 9000-frame window**, not measured to any horizon.

### 3. The comparison windows do not overlap — and that may invalidate C-041

| | first `$03:8026` execution | measurement window used |
|---|---|---|
| peer | **frame 3857** | 9000 |
| ours (C-041) | **never observed** | **f0–f3700** |

The peer's tick **never fires inside f0–f3700 either.** So C-041's window
contains no frame in which the reference build would have executed the tick
once. C-041 measured "0 executions in f0–f3700", which is true, and it does
**not** license "the tick never executes" — the same shape as the f3301/f3271
100-frame-bracket artifact already retracted once. **This is the single next
measurement** and it is cheap: re-run the per-bank PC dump out past f4000.

## Method, and what was changed

The peer's published API has no PC trace (C-032) and no WRAM write hook — it
offers only bounds-checked *reads*. So the write-watch is a **local study
patch**, and here it is in full, because a study patch that is not disclosed is
just a hidden difference between two builds:

- Clone: `Junior-Jones/SimCity-SNES-Static-Recomp` @ `454eb0a`, no licence
  declared. Private study; nothing copied into this repository.
- Build: `RelWithDebInfo`, core target `simcity-static-recomp`, host gcc.
- **Patched file:** `static-recomp/src/sc_v11_bus.c`, one hook at the top of
  `sc_v11_bus_write8()` — the single bus-write funnel
  (`sc_v11_bus_write16` decomposes into two `sc_v11_bus_write8` calls).
- **Kept out of every shipped path.** The edit exists only in the throwaway
  clone at `/tmp/opencode/peers`. No peer source is vendored here; the pristine
  copy is retained at `/tmp/opencode/peers/sc_v11_bus.c.orig`.
- Driver: our own `study/peer-linux/jjhead.c`, unmodified. Input:
  `scripts/d_city_kbd.script`, 8067 scheduled frames, 41 presses.
- Environment: `T093_WATCH_LO=0x0B51 T093_WATCH_HI=0x0B52`, log to a path
  outside the repository.

### The hook needed two corrections before it told the truth

Recording these because the first two versions both produced confident garbage:

1. **The watch key must be the WRAM index, not the bus address.** An absolute
   operand is banked by the *data* bank at access time —
   `sc_v11_ea_abs()` returns `(dbr<<16)|op` — and the same 128 KiB of WRAM is
   reachable as bank `$7E`, bank `$7F`, or a low bank with offset `< $2000`.
   Watching `0x000B51` logged **2 writes in 9000 frames** while `$0B51`
   visibly incremented 27 times: it caught only the two frame-0 writes made
   with `dbr=$00` and missed every `dbr=$7E` write. The key is now the WRAM
   index, resolved with the core's own `sc_wram_index` rule.
2. **The core's `cpu.pc` is the NEXT PC, not the writer's.**
   `SC_STATIC_CONTEXT_BEGIN(addr, len, open_bus, next_pc)` ends with
   `c->pc = next_pc`, and it runs *before* the instruction body. A watch that
   trusted `cpu.pc` reported the writer as `$03:8029`.

Both were caught only because the result was cross-checked against ROM bytes.
A hook that had agreed with itself would have shipped both errors.

## The cross-check that decides it

ROM is LoROM: `addr = ((file_off & 0x7FFF) | (((file_off>>15) & 0x7F) << 16))`,
verified by locating `EE 51 0B` at file offset `0x18026` and reading the header
at `0x7FC0` = `SIMCITY` (`0xFFC0` is `$FF` filler). MD5
`23715fc7ef700b3999384d5be20f4db5`, 524288 bytes.

| what the watch logged | bytes in ROM at that address | is it a store to `$0B51`? |
|---|---|---|
| `$03:8029` | `AD C7 0D` = `LDA $0DC7` | **no** — cannot be the writer |
| `$03:8026` | `EE 51 0B` = `INC.w $0B51` | **yes** — length 3 → next PC `$03:8029` ✓ |
| `$03:C781` | `9C 1D 0B` = `STZ $0B1D` | **no** — a *different* address |
| `$03:C77E` | `9C 51 0B` = `STZ.w $0B51` | **yes** — next PC `$03:C781` ✓ |

The logged PC is not a store; the PC three bytes earlier is, and its length
explains the gap. That is the identification, and it is a falsifiable one: if
the +3 shift were wrong, the logged address would itself have been a store to
`$0B51`.

## Every writer of `$0B51`, and one the ROM census could not see

Enumerating the peer's generated shards for stores whose target is `$0B51`
yields **three** absolute-mode writers, and they match the project's existing
census exactly:

| writer | bytes | instruction | executed in this run |
|---|---|---|---|
| `$03:8026` | `EE 51 0B` | `INC.w $0B51` | **yes, 27×** |
| `$03:C77E` | `9C 51 0B` | `STZ.w $0B51` | yes, 1× at f2985 |
| `$03:C9E3` | `8D 51 0B` | `STA.w $0B51` | no |

The watch, however, logged a **fourth** writer the census could not contain:

**`$00:8023` = `95 00` = `STA dp,x`** — a *direct-page indexed* store with a
**one-byte** operand. The watch captured it with `D = $0000`, `X = $0B51`, so
`dp + D + X = $0B51`, twice, at frame 0, value 0.

A census built by scanning for the operand bytes `51 0B` is structurally blind
to `STA dp,x`: the operand is `00` and the effective address does not exist
until D and X are known at run time. This is the same failure shape as the
earlier `JSL (abs)` mis-scan (matched the operand `7A 1F`, never checked the
`$FC` opcode). **"Exactly one writer" is not established by an operand scan.**

## Reproducing

```bash
git clone --depth 1 https://github.com/Junior-Jones/SimCity-SNES-Static-Recomp \
    /tmp/opencode/peers/src
cmake -S /tmp/opencode/peers/src -B /tmp/opencode/peers/build \
    -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build /tmp/opencode/peers/build --target simcity-static-recomp -j"$(nproc)"
# apply the hook described above to static-recomp/src/sc_v11_bus.c, then:
gcc -O2 -g -o /tmp/opencode/peers/run/jjwatch study/peer-linux/jjhead.c \
    -I/tmp/opencode/peers/build -I/tmp/opencode/peers/src/static-recomp/include \
    /tmp/opencode/peers/build/static-recomp/libsimcity-static-recomp.a \
    -lstdc++ -lm -lpthread
T093_WATCH_LO=0x0B51 T093_WATCH_HI=0x0B52 \
T093_WATCH_LOG=/tmp/opencode/peers/out/watch.log \
    /tmp/opencode/peers/run/jjwatch "$PWD/SimCity (USA).sfc" \
    /tmp/opencode/peers/run/cold.srm /tmp/opencode/peers/run/srm.out \
    9000 scripts/d_city_kbd.script /tmp/opencode/peers/out
```
