| **R-047** | "there is a year transform" | `$0B53` IS a plain BCD year. `$03:C490 CMP ($C4DC),Y` compares it 16-bit against `1900 1900 1900 1901 1901 1905`. |

These two refutations came from the same run (T112) that established the census

because `$0012` is not the gate, its **timing** has never been tested.

### MEASURED facts — load-bearing

1. **Ours: `$0012` written exactly twice**, f0 `$00:8023` (`STA dp,X`) and
   f3271 `$03:D2AA` (`STA $0012`). Never cleared. Peer: f0 and f2998. Same
   `$03:D2AA` writes both, 16-bit store (`$0013=$00` then `$0012=$01`, `D=0`).
2. **Bank `$03` executes NOTHING in f3272–f3400.** Zero interpreted PCs, zero
   AOT block entries. The last frame of bank `$03` execution is **f3271**
   (16 steps, epilogue ending `RTL` at `$03:D2B7`).
3. **The `$0014` scheduler trace is the same twelve milestones in both builds**
   (T112 §4): same order, same writers, same values. `$03D283` runs ONCE in each,
   f3259–f3271 ours, f2998–f3010 peer. So `$00:804D` → `JSL $03D283` is
   city-creation, not the per-frame engine, in either build.
4. **The peer's bank `$03` re-enters at f3068 — 70 frames after its `$0012`
   latch at f2998.** In ours, the latch is at f3271 and nothing re-enters.
   **The 273-frame timing difference has never been tested.** This is what
   changes in this experiment.
5. **The display path is intact and HDMA** (R-045). Poking `$0B53` renders the
   year; `$0B55` renders the month. `$0B51` is only the counter.
6. **The tick instruction** (`$03:8026` `INC.w $0B51`) **executes 0 times** in
   14 000 frames in ours (C-066), first at f3857 in the peer (T093).
7. **The positive control is `COUNT_PC=0x009311` = 1 942.6/f ±0.66%** (T106,
   five runs, all byte-identical to the known-good 1 929.9/f within the
   wall-clock-dependent bound).

## 1. Hypothesis

**If `$0012` is forced to `1` at ~f3000 — before its natural f3271 latch — and
bank `$03` then becomes alive (tick runs, `$0B51` increments, dates advance),
then the 273-frame timing difference between the builds IS the causal gate.**

**If `$0012` is forced early and nothing changes, then the latch timing is NOT
the gate.** The divergence must lie elsewhere (stack, NMI delivery timing, DB,
something not yet watched).

### Sub-hypothesis: the 273-frame window

The peer latches `$0012` at f2998 and enters bank `$03` at f3068. Ours latches
at f3271. **What occupies f2998–f3271 in ours that the peer has finished doing?**
If it is a longer version of the same city-creation work, the timing difference
is a *symptom of a slower initialisation phase*, not an independent gate.

**NOT measured.** This window has never been instrumented.

## 2. Method

### 2.1 The poke mechanism

`scripts/d_city.script` reaches a live city by f3224 (last `mouseclick right`).
A `poke` entry after that fires on the NEXT frame the script processes, which is
f3334 in the base script (110-frame wait after the last mouseclick). That is
**after** the natural f3271 latch, so it would answer nothing.

**The fix is a new script** that inserts the pokes **before** the city loads:

```
poke 0012 01    # write byte low
poke 0013 00    # write byte high (full 16-bit = $0001)
```

Two pokes, back-to-back, to reproduce the same 16-bit store `$03:D2AA` makes at
f3271 (and f2998 in the peer). Placed at ~f3000, well before the natural latch.

### 2.2 Script layout

The new script `t118_early_0012_poke.script` extends `d_city.script`:

```
[the 24-entry city-creation route, ending f3224]
wait 110        # arrives ~f3334 — TOO LATE for the hypothesis
                # INSTEAD: insert pokes earlier
```

**The correct insertion point is BEFORE the city loads.** The city state block is
written once at f3259 (`$03:C63F` LDA #$076C / STA $0B53, `$03:C77E` STZ.w $0B51).
The pokes must fire **between f3000 and f3259**, before the city-state block is
written, and ideally before f3271 so the poked `$0012` value is what `$03:D2AA`
sees on exit.

**The insertion is inside the base script, not appended.** A `wait` entry before
the city's final mouseclick positions the poke at the target frame.

### 2.3 Instrumentation plan

Three runs, each with its own control, foreground on the Deck:

| run | script | key instruments | total frames |
|---|---|---|---|

### 2.4 Observable — `$0B51` is the decisive test

| outcome | `$0B51` | interpretation |
|---|---|---|
| **Verdict 1** | increments (first at ~f3857 like the peer) | `$0012` **timing** IS the gate. The 273-frame difference is causal. |
| **Verdict 2** | stays at 0 | `$0012` timing is NOT the gate. R-046 confirmed a second way. Divergence lies elsewhere. |
| **Verdict 3** | control silent or run void | **Inconclusive.** Say which, stop. |

**Controls that must fire:**
- `COUNT_PC=0x009311` > 0 in every run (the vblank spin body). A silent control =
  void run.
- R2 (no poke) must reproduce the known absence of bank `$03` execution after
  f3271. If it does not, the instrument itself is broken and all runs are void.
- `$0B51 = 0000` at f3300 in R2 (baseline, confirmed by T102).

### 2.5 Bank `$03` execution census — both tiers

`INTERP_DUMP_BANK=03` enumerates distinct interpreted PCs (C-041's method).
`AOTBLK=3000-9000` with `SNESRECOMP_TRACE=1` enumerates AOT block entries
(T104, C-046c). **Both are required.** A bank absent from the interpreted
histogram may still be executing natively (C-039c).

**Also watched:** `$0E15` writes (secondary, given the attribution problem from
R-048: the ROM byte at `0x18222` is `9C` = `STZ $sr,S`, not `STZ dp`).
`$0012` writes (primary, to confirm the poke landed and was not overwritten).
