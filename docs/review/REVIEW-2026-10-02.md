## Findings

### F-01 — BLOCKER — The delivery gate asserts a cause that measurement refuted

**Rubric:** E-03, E-01

`scripts/clock-gate.sh:262-278` prints, under the literal heading **"What is
established"**:

> the main loop at `$00804D` branches on vblank-done token `$0012` … `$0012` is
> written in exactly one place in the whole ROM … Measured 0 in 13 of 13
> frame-boundary samples, so the per-vblank body `CODE_008061` never runs … So
> the gate is `$0012`, and `$0012` waits on the scheduler loop at `CODE_03D287`
> exiting, which needs bit 7 of `$0014`.

Measured 2026-10-02 at `afceeec` (`SNESRECOMP_WRAM_DUMP_AT` at
f3400/3600/4000/5000/5999):

```
$0012  f3400=0001 f3600=0001 f4000=0001 f5000=0001 f5999=0001
$0014  f3400=8000 f3600=8000 f4000=8000 f5000=8000 f5999=8000
```

The claim's own stated evidence is what refutes it. `$0012` is not 0. Bit 7 of
`$0014` is not clear. The rubric names this exact class a BLOCKER: "a retracted
cause presented as fact."

The same chain is asserted at 12 further sites, retracted at **zero**:
`RE_CITY_FREEZE.md:1726-1731` (entry (a), the first dated entry), `:1907`,
`:1967`, `:2003`, `:2137`, `:2681`, and `cross-load-peer-save.sh:115`.

**Closure:** the FAIL block names no token, address or routine, **and**
`scripts/check-retracted-claims.sh` exits 0.

### F-02 — BLOCKER — `make test` cannot pass off the author's machine; README says it was fixed

**Rubric:** C-04

`tests/test_deterministic_replay.c:38-39` and `:58-59` hardcode:

```c
"--script /home/seyon/dev/Games/PC/simcity/tests/deterministic_replay.script "
"\"/home/seyon/dev/Games/PC/simcity/SimCity (USA).sfc\" "
```

README.md:183-184 states: *"The determinism gate is now relocatable — it used to
hardcode one developer's checkout path and could only pass there."*

It was not fixed. Verified by relocating the tree to `/tmp/opencode/reloc2`
with **no ROM present in either tree**: `make build` exits 0 and `ctest` reports
**2/2 passed** — because the test reaches back into the author's home and runs
the original repo's script against the original repo's ROM. The binary exits 1
on a missing ROM (verified directly: `FATAL: unable to load rom`, exit 1), so on
any machine without that exact path the test **fails outright**. C-04's second
clause — "no absolute path to the author's home appears in `tests/`" — fails on
inspection.

C-04 as literally written in the rubric (`cp -r .`) would copy the ROM, which the
project's own legal rule forbids. The check is therefore not executable as
written; the relocated run above is the closest legitimate equivalent, and it
found a real defect the written check would have masked.

**Closure:** `grep -rn '/home/seyon' tests/ | wc -l` is 0, and `make test` passes
in a relocated tree using a caller-supplied ROM.

### F-03 — BLOCKER — A refuted premise recorded as a retraction

**Rubric:** E-01

`docs/CLAIMS_REGISTER.md` §1 item 6 lists *"CODE_008061 / CODE_00825F never
run"* as **RETRACTED**, and `clock-gate.sh:273` still prints it. Its evidence was
`$0012 == 0`, which F-01's measurement refutes. A false premise voids an
inference; it does not establish the converse. Whether `CODE_008061` executes
**has never been measured**.

Recording it as retracted replaces one unmeasured assertion with another of
opposite sign — the exact mechanism that produced the paired `$0B51` retraction
(F-04).

**Closure:** the claim's status is stated as OPEN with its invalidated premise
named, not RETRACTED; and "never runs" appears nowhere as an assertion about
`CODE_008061`.

### F-04 — BLOCKER — A correct measurement retracted by an argument

**Rubric:** E-01

`RE_CITY_FREEZE.md:2196-2206` (entry (g)) records, for `$0B51`:

1. asserted *"$0B51 stays 0 → the tick never runs"* — **correct**;
2. retracted *"it's a free-running mod-4 counter, reads 0 one frame in four, so
   it proves nothing"* — **wrong**;
3. re-asserted as monotonic — correct.

The replacement for a correct measurement was an interpretation, offered without
a second measurement. The document names the cause itself: *"foi a minha segunda
retractação do mesmo endereço, em direcções oppostas"* — the second retraction
of the same address, in opposite directions.

**Closure:** the rule *"a measurement is retracted only by a second independent
measurement; an interpretation may be retracted by reasoning"* is in
`docs/DEFINITION_OF_DONE.md` and enforced by a check.

### F-08 — MAJOR — An executable script that provably cannot work

**Rubric:** E-06

`scripts/cross-load-peer-save.sh` is mode 0755, has **no dead-end banner, no
deprecation note and no exit guard**, and its header argues the case for why the
experiment *should* work. Line 115 pokes `("$0012 gate", 0x12, 1)` — a

32,746 bytes of `0xFF` around `"SIM"`, identical md5 from a naming-screen session

Nothing in the file tells the next reader it cannot work. The knowledge went into
a commit message instead of the artifact.

**Closure:** deleted, or the first 20 lines state the disproof and it exits

### F-09 — MAJOR — Three green gates cannot fail on the open bug

**Rubric:** G-01

`make test` is 2 tests, one of which runs 30 frames. `make test-rom` inspects
frames 200-800, all before the city exists at ~f3378. `make perf` runs 600 frames
and on the Deck is **frame-locked** — five runs, all exactly 10.549 s — so it
cannot observe guest cost at all. Only `make clock` reaches the city, and it
correctly fails.

DoD clause **D2.2** — a gate must prove the city is real from the guest's own
state — is unimplemented, which is precisely how "the city does not load"
survived several sessions unchallenged.

**Closure:** `make clock` prints the guest's own year word and fails if it is
zero; D2.4's dead-build baseline is printed beside the byte threshold.

### F-11 — MINOR — The Deck cannot build this project

**Rubric:** G-04

Verified over ssh 2026-10-02: `/usr/bin` is read-only (SteamOS immutable rootfs)
and `/usr/include/stdio.h` is absent, so `make build` on `deck@steamdeck` fails
at configure. `gcc` links a trivial program but the project needs libc headers.
All Deck figures therefore come from a binary built on the dev host and `scp`'d —
including the 56.88 fps and the reproduced clock failure.

**Closure:** every Deck measurement states that the binary was cross-built, and
names the host that built it.

### F-12 — MINOR — `bank00.cfg:44` comment contradicts its own bytes

**Rubric:** C-03

The comment reads `STZ $00B9 / INC $00C7 / LDA $00B9 / BEQ / RTS`. The bytes at
`0x130D` are `e2 20 64 b9 e6 c7 a5 b9 f0 fa 60`: `E6 C7` is **`INC $C7`**
(direct page), not `INC $00C7`, and the range starts two bytes early at the
preceding `SPC $20` rather than the spinlock's real first instruction at
`0x130F`. Harmless (over-exclusion), and already noted by T077 — but a comment
mis-stating an addressing mode in the line that fixes a mask bug is a poor place
to be casual.

**Closure:** the comment reads `INC $C7`, and the range starts at `0x1311` or a
comment says why `0x130D` is intended. Changing it regenerates code, so it must
be paired with a regen and a gate run.

**1. Severity of F-13 — Cínico MINOR, this review MAJOR.** Cónico's threshold is
cost ("<10 minutes and no gate change"); by that rule this is a text edit. I
rated it MAJOR because acting on line 1109 reintroduces a diagnosed-and-closed

is the one that matters for closure, and it is deliberately the stricter one.**

**2. Severity of F-10 — Pragmático BLOCKER, this review MAJOR.** Pragmático
argued the delivery gate is one experiment from green, so the unrun experiment
is a BLOCKER. I demoted it to MAJOR because the open question is *already
correctly documented* as open in README and the DoD; a known, labelled gap is
not a false claim, and F-01/F-03/F-04 already carry the rejection. **Pragmático's
rating is recorded as a dissent and I think it is defensible: if the question is
"is this deliverable", the answer is no, for this reason.**

**3. Utilizador submitted one non-finding.** Its second entry praises the
README's honest status line. Under the protocol's rejected patterns ("the code
is good" — adjectival, not evidence) **this is rejected by format** and is not
carried as a finding. Its content is preserved in
`aes/peer-reviews/clock-2026-10-02/findings/04-utilizador.md` because it is the
only persona to record what the project does *right*, and a review that lists
only faults misrepresents the tree.

**Convergence, recorded honestly.** Cínico, Utilizador and Pragmático
independently produced F-01 (the gate's false cause) as their top item. That is
convergence, not independence — I am one model in one context, and I ran all four

independence requirement.** See the deviation below. The convergence is still
evidence that the finding is the most salient one, and it is *not* evidence that
four independent reviewers found it.

## Protocol deviations, stated rather than hidden

1. **No independent reviewers.** The protocol requires 2+ reviewers from
   different model families, or a fallback convening 4 personas as **fresh
   subagents**. This session has **no subagent tool**. All four personas were run
   by one model in one context, sequentially, each writing its findings to a
   separate file before the next was written. That preserves *non-sharing of
   findings* but **not** independence of judgement. Per the protocol's own
   enforcement rule — "if multi-perspective review not completed, review is
   INVALID" — **this review is a valid single-reviewer review with a
   multi-perspective supplement, not a valid multi-perspective review.** The
   BLOCKERs do not depend on it: F-01, F-02, F-03 and F-04 are each
   independently verifiable by the commands in their evidence blocks, and any
   reviewer with a shell can confirm them.

2. **Human validation is outstanding.** The protocol requires the moderator to
   emit an executable validation script that a **human, not the author**, runs
   and records. It is at `docs/review/validate-findings.sh`. **It has not been
   run by anyone other than me.** Until it is, the findings are unconfirmed by
   the protocol's own standard, even though I ran every command while writing
   them.

3. **The AES skill's own rubric was not substituted.** The skill's
   `templates/review-rubric.md` is NARRATIVE-INTEGRITY-SUITE, about the AES
   toolkit's shell scripts. Purista recorded a dissent worth keeping: under that
   rubric, F-03 and F-04 — the two epistemic BLOCKERs — would have scored as
   *good practice*, because "retract a claim whose evidence failed" and "correct
   the record" are textbook hygiene. **The substitution would not have changed
   the verdict; it would have inverted the reasoning.** That is the strongest
   available evidence that the pre-registered rubric was the right choice, and it
   is why the rubric was placed in `docs/` and hashed before this review began.

4. **Two AES instruments were run and their output rejected as inapplicable.**
   `aes-debt`, `aes-narrative` and `aes-conflict` all pin `AES_ROOT` to the
   toolkit install and report on its own repository. `aes-conflict`'s numbers are
   produced by a target wired as `|| true`, so it cannot fail even there. Their
   output is recorded in the phase reports and is explicitly **not** used as
   evidence about this project.

## Rubric criteria with no finding

**D-03** and **D-04** (per-frame headroom; budget double-counting) are the two
criteria this review could **not** adjudicate, and that is a real limit. D-03
requires `SNESRECOMP_HOST_PROFILE=1` over 1200 frames; the figures behind the
